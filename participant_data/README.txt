この1チーム分の人の集まりをコホートと呼びます。

[提出のしかた]
このキットのデータは練習用です（練習フェーズは 8/8 に終わりました）。
本番の提出には、事務局から届いた本番のデータと、自分のチームの token.txt を使います
（このキットに入っている token.txt は、sample_submissions/ の中のものも含めて練習用です）。

提出は CodaBench で、1回の提出を zip 1つにまとめます。ファイルは zip の直下に置きます（フォルダを作らない）。
  加工フェーズ: 配られた B.csv を匿名化して C.csv を作り、C.csv と token.txt を zip にして提出。
  攻撃フェーズ: 開始時に配られる C_<k>.csv・aia_challenge_<k>.csv・mia_columns.json をもとに
                F_mia.csv・F_aia.csv を作り、F_mia.csv・F_aia.csv・token.txt を zip にして提出（8回まで）。
提出しただけではリーダーボードに載りません。CodaBench の提出一覧（My Submissions）で、載せたい提出の
Add to Leaderboard を押してください。順位の計算に使われるのは、フェーズ終了時点で載せている1件だけです。
提出物の様式はルールブック §5.1・§5.2、提出できる回数とリーダーボードは §5.3 にあります。
形の実例（練習データで作ったもの）:
  sample_submissions/process_sub.zip（加工）・sample_submissions/attack_sub.zip（攻撃）

[ローカルでの自己採点]
B_self.csv は B_practice.csv に、希少な患者かどうかの正解ラベル is_rare 列を足した「自己採点用の拡張版B」です。
有用性はサーバに出さなくても手元で採点できます（CodaBenchと同じ点数。participant_data/ をカレントディレクトリにして実行）:
  docker run --rm -v "$PWD":/w hajimeono/pwscup2026-kit:main-process-20260912 score /w/C.csv --dist /w
utility_ref.json・scoring_config.yaml は採点器が使う参照値とパラメータです（消さないでください）。
※保護(protection)・攻撃力は他チームの情報が要るため手元では採点できません（サーバのみ）。

[ノートブック教材（任意）]
キットの notebooks/ に7本あります（このフォルダの外・スターターキットの直下）。
  はじめてのPWSCup.ipynb  … 加工と攻撃を1周ずつ体験する（20〜30分）
  採点のしくみ.ipynb      … 得点がどう決まるか・何をすると点が上下するか（15〜20分）
  打ち切り整合_cens.ipynb … 発症も死亡もしていない人の time は何年にすればいいか（10分）
  相関の一致_corr.ipynb   … 列ごとの分布は合っているのに、相関の点が低いのはなぜか（10分）
  裾の一致_tail.ipynb     … 平均も標準偏差も合っているのに、裾の点が低いのはなぜか（15分）
  重複行_no_dup.ipynb     … 同じ行が何度も出てくると、何がいけないか（5分）
  行の新規性_novel.ipynb  … A_bg の行をそのまま C に入れると、どうなるか（10分）
  cd starter && uv sync --extra notebook && uv run jupyter lab ..
教材であってルールの正本ではありません。正本はルールブックと sample_submissions/ です。
提出物は CSV とテキストファイルだけなので、Python 以外の言語・ツールで作ってもかまいません
（自己採点器・検証器を動かすには Python か Docker が要ります）。
